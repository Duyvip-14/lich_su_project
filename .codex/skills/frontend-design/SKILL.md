# Frontend Design Skill
## Vietnamese History Platform

You are responsible for maintaining a world-class frontend design system
for a long-term Vietnamese History digital platform.

This is not a generic student project.

Treat every interface decision as part of a scalable product that may serve
students, teachers, parents, history enthusiasts, schools, organizations,
and future educational partners.

The frontend must feel:
- modern
- memorable
- trustworthy
- culturally meaningful
- emotionally engaging
- easy to use
- scalable
- production-ready

Never produce a generic AI-generated dashboard unless explicitly required.

---

# 1. PRODUCT VISION

The product exists to make Vietnamese history:

- easier to understand
- easier to remember
- more visual
- more interactive
- more emotionally engaging
- more accessible to young people
- more useful for teachers and parents
- more enjoyable than traditional textbook learning

The interface should make users feel that Vietnamese history is alive,
not something distant or boring.

Design for curiosity.

Design for exploration.

Design for storytelling.

---

# 2. DESIGN PHILOSOPHY

Always prioritize:

1. Clarity
2. Historical storytelling
3. Emotional connection
4. Visual hierarchy
5. Consistency
6. Accessibility
7. Performance
8. Responsive behavior
9. Maintainability
10. Scalability

The user should always understand:

- Where am I?
- What am I looking at?
- What can I do next?
- Why is this information important?

Never sacrifice usability for decoration.

---

# 3. VISUAL IDENTITY

The visual identity should be inspired by Vietnamese history and culture
without becoming old-fashioned.

Prefer a balance between:

- modern educational technology
- museum exhibition design
- historical storytelling
- Vietnamese cultural identity

The design should feel premium but approachable.

Avoid excessive ancient-paper effects, yellow parchment backgrounds,
heavy ornamental borders, or stereotypical historical decorations.

Historical elements must support the experience, not dominate it.

---

# 4. COLOR SYSTEM

Use colors intentionally.

Recommended visual direction:

Primary:
- deep historical red
- warm Vietnamese red
- dark crimson

Supporting:
- warm gold
- bronze
- neutral beige
- warm gray
- ivory
- charcoal

Optional contextual colors:
- green for nature or geography
- blue for information
- amber for historical highlights

Never use too many strong colors simultaneously.

The interface should have one dominant color language.

Do not use random colors between pages.

Every color should have a role.

Examples:

Primary action → brand red

Historical highlight → gold

Success → green

Information → blue

Warning → amber

Danger → red

---

# 5. TYPOGRAPHY

Typography is extremely important.

Vietnamese text must always remain readable.

Prioritize fonts that support Vietnamese characters correctly.

Use clear hierarchy:

H1 → page identity

H2 → major sections

H3 → content group

Body → reading

Caption → metadata

Avoid excessively decorative fonts for long content.

Historical or display fonts may be used only for:

- hero headings
- historical period titles
- exhibition-style titles

Never use them for paragraphs.

Maintain comfortable line-height and reading width.

Long historical articles should not stretch across the entire screen.

---

# 6. LAYOUT

Every layout must have clear visual hierarchy.

Preferred page structure:

Header
↓
Primary page identity
↓
Main content
↓
Supporting content
↓
Related exploration
↓
Footer

Use whitespace deliberately.

Never compress everything together.

Avoid excessive card grids.

Not every piece of information needs to be inside a rounded rectangle.

Use:

- editorial layouts
- timelines
- visual storytelling sections
- split layouts
- maps
- historical imagery
- contextual panels
- progressive disclosure

when appropriate.

---

# 7. CORE DESIGN RULE

Before creating UI, ask:

"What is the main thing the user should notice first?"

Then design the hierarchy around that answer.

Every screen must have a clear primary focus.

Never create a screen where all elements have equal visual weight.

---

# 8. HISTORICAL CONTENT DESIGN

Historical content must be easy to scan.

Important information may include:

- event name
- year
- location
- historical period
- people involved
- cause
- event
- consequence
- historical significance

Avoid presenting history as giant text blocks.

Prefer structured storytelling.

Example:

Context
↓
What happened
↓
Key people
↓
Result
↓
Historical significance
↓
Related events

Whenever possible, connect events visually.

History should feel like a network of causes and consequences.

---

# 9. TIMELINE EXPERIENCE

Timeline is one of the most important UI patterns.

Timeline designs must:

- clearly show chronology
- distinguish historical periods
- highlight important milestones
- remain readable on mobile
- allow progressive exploration

Avoid timelines that require horizontal scrolling without clear controls.

Allow users to understand:

Before
→ Event
→ After

Major historical events should visually stand out from minor events.

---

# 10. HISTORICAL PERIODS

The platform may organize Vietnamese history into major periods.

Each historical period should have:

- distinct visual identity
- representative imagery
- short description
- timeline context
- important events
- important figures
- related learning content

However, maintain global design consistency.

Different periods may feel different,
but they must still belong to the same product.

---

# 11. USER TYPES

Design should support multiple roles.

Possible roles include:

- normal users
- students
- teachers
- parents
- administrators

Do not expose unnecessary complexity to normal users.

Student experience:
- simple
- visual
- interactive
- motivating

Teacher experience:
- structured
- efficient
- classroom-friendly

Parent experience:
- progress-focused
- easy to understand

Administrator experience:
- operational
- data-focused
- efficient

Role-specific interfaces may differ significantly.

---

# 12. HOME PAGE

The home page must immediately communicate:

"This is a modern platform for exploring Vietnamese history."

Avoid generic landing page templates.

Strong homepage possibilities:

- historical hero moment
- featured event today
- "On this day in history"
- timeline exploration
- map exploration
- important figures
- featured historical periods
- learning challenges

The first viewport must have strong identity.

Do not fill the hero with meaningless marketing text.

---

# 13. DAILY HISTORY FEATURE

The product may contain a daily historical anniversary feature.

Design this as a meaningful recurring experience.

Example:

"Ngày này năm xưa"

It should include:

- date
- event title
- historical image
- short summary
- why it matters
- explore button

This feature should feel special,
not like another generic card.

---

# 14. SEARCH EXPERIENCE

Search must be extremely useful.

Users may search by:

- event
- person
- location
- historical period
- year
- keyword

Search results should clearly distinguish content types.

Never show users a confusing list of identical cards.

---

# 15. HISTORICAL MAPS

When displaying geographical history:

Use maps when they genuinely improve understanding.

Examples:

- battles
- kingdoms
- territorial changes
- migration
- historical routes

Map UI should always provide explanatory context.

Never rely on map visuals alone.

---

# 16. INTERACTION DESIGN

Interactions should feel smooth and intentional.

Use subtle transitions.

Recommended:

- hover feedback
- focus feedback
- active state
- loading state
- empty state
- disabled state
- error state
- success state

Avoid excessive animation.

Never animate everything.

Animation must explain relationships or improve orientation.

---

# 17. MICROINTERACTIONS

Use microinteractions for:

- quiz answers
- timeline milestones
- bookmarks
- favorites
- progress
- navigation
- content expansion

Feedback should happen immediately after user action.

---

# 18. RESPONSIVE DESIGN

Every interface must work on:

- mobile
- tablet
- laptop
- desktop

Mobile is not an afterthought.

Never simply shrink desktop layouts.

On mobile:

- simplify hierarchy
- reduce unnecessary content
- stack intelligently
- preserve primary actions
- avoid tiny touch targets

Minimum touch target should be comfortable for mobile users.

---

# 19. ACCESSIBILITY

Accessibility is mandatory.

Ensure:

- readable contrast
- keyboard accessibility
- visible focus states
- semantic HTML
- alt text
- usable forms
- understandable error messages

Never rely only on color to communicate meaning.

---

# 20. COMPONENT SYSTEM

Prefer reusable components.

Possible components:

HistoricalCard
HistoricalEvent
HistoricalFigure
Timeline
TimelineItem
PeriodCard
DailyHistory
HistoricalMap
SearchResult
QuizCard
ProgressIndicator
RelatedEvent
HistoricalImage
ArticleSection
SourceReference

Do not duplicate UI patterns unnecessarily.

Before creating a new component,
check whether an existing component can be reused or generalized.

---

# 21. DESIGN SYSTEM CONSISTENCY

Maintain global rules for:

- border radius
- shadows
- spacing
- typography
- buttons
- inputs
- cards
- modals
- navigation
- containers

Do not invent new styling values randomly.

Use design tokens whenever possible.

Example:

spacing
radius
font size
colors
shadow
breakpoints

---

# 22. BUTTONS

Buttons must communicate priority.

Primary:
main action

Secondary:
alternative action

Tertiary:
low-priority action

Danger:
destructive action

Do not create five buttons with identical visual importance.

Button labels should be clear.

Bad:
"Click here"

Good:
"Khám phá sự kiện"

---

# 23. CARDS

Avoid overusing cards.

Use cards when content represents a meaningful independent entity.

Examples:

- historical event
- figure
- period
- lesson
- quiz

Do not wrap every section in cards.

Avoid:

card inside card
inside another card

---

# 24. IMAGES

Historical imagery is a major part of the experience.

Images must:

- have clear purpose
- maintain correct aspect ratio
- avoid distortion
- have meaningful alt text
- use consistent presentation

When historical images are unavailable,
do not use unrelated decorative stock photography.

---

# 25. CONTENT PRIORITY

Historical accuracy and readability are more important than visual novelty.

Never change factual historical content merely to make layout easier.

Design must adapt to content.

Content should not be distorted to fit design.

---

# 26. EMPTY STATES

Never show blank screens.

Empty states should explain:

- what is missing
- why it is empty
- what the user can do

Example:

"Chưa có sự kiện được lưu."

Action:

"Khám phá các sự kiện lịch sử"

---

# 27. LOADING STATES

Use appropriate loading UI.

Prefer:

- skeletons
- progressive loading
- lightweight placeholders

Avoid blocking the entire screen unnecessarily.

---

# 28. ERROR STATES

Errors should be understandable.

Never expose technical stack traces to normal users.

Bad:

"Error 500"

Better:

"Không thể tải dữ liệu lịch sử lúc này. Vui lòng thử lại."

---

# 29. PERFORMANCE

Frontend design must consider performance.

Avoid:

- unnecessarily large images
- excessive animation
- massive JS libraries
- unnecessary re-renders
- bloated components

Lazy-load heavy media when appropriate.

Performance is part of UX.

---

# 30. CODE QUALITY

Frontend code must be:

- readable
- reusable
- maintainable
- modular
- predictable

Avoid giant components.

Separate:

layout
logic
data
presentation

when appropriate.

---

# 31. PRESERVE FUNCTIONALITY

When redesigning existing screens:

Do NOT break working functionality.

Before redesigning:

1. inspect current behavior
2. identify dependencies
3. understand routes
4. understand data flow
5. understand API usage
6. understand state

Then redesign.

Visual improvement must never silently remove functionality.

---

# 32. DO NOT OVERWRITE WITHOUT REASON

Before replacing an existing implementation:

Explain internally why replacement is necessary.

Prefer incremental improvement when appropriate.

Do not rewrite entire working modules just because a cleaner implementation exists.

---

# 33. EXISTING PROJECT FIRST

Always inspect the existing codebase before designing.

Understand:

- folder structure
- framework
- routing
- existing components
- styling system
- API integration
- reusable assets

Never assume technology without inspection.

---

# 34. PRODUCTION MINDSET

Do not create demo-quality UI.

Avoid:

- fake data unless explicitly needed
- placeholder text
- unfinished buttons
- dead navigation
- decorative UI with no function

When placeholders are necessary,
clearly mark them.

---

# 35. AI DESIGN ANTI-PATTERNS

Avoid common AI-generated design patterns.

Examples:

- excessive gradients
- giant hero gradients
- random purple/blue themes
- every section inside cards
- excessive glassmorphism
- unnecessary glowing effects
- too many rounded pills
- excessive icons
- floating meaningless statistics
- fake testimonials
- generic SaaS layouts

This project must have its own visual identity.

---

# 36. VIETNAMESE CULTURAL CONTEXT

Use Vietnamese cultural elements carefully.

Possible inspiration:

- Đông Sơn patterns
- traditional architectural forms
- historical maps
- bronze textures
- red and gold ceremonial colors
- Vietnamese calligraphy influence

These elements must be subtle.

Never turn the interface into a historical costume.

Modern usability comes first.

---

# 37. EDUCATIONAL UX

Learning interfaces should help users remember information.

Use:

- visual associations
- chronological relationships
- cause-and-effect relationships
- maps
- comparisons
- interactive quizzes
- spaced repetition
- contextual links

Avoid passive reading as the only learning method.

---

# 38. QUIZ EXPERIENCE

Quiz UI should feel motivating.

After each answer:

- clearly indicate correctness
- explain why
- optionally connect back to relevant historical content

Avoid only showing:

"Correct"

or

"Wrong"

Learning feedback matters.

---

# 39. USER PROGRESS

If progress systems exist:

Show progress clearly.

Possible elements:

- completed periods
- completed lessons
- quiz accuracy
- learning streak
- saved events
- favorite figures

Avoid manipulative gamification.

Gamification should support learning.

---

# 40. NAVIGATION

Navigation should remain simple.

Primary navigation should reflect major product areas.

Avoid deeply nested menus.

Users should be able to reach important content within a few actions.

---

# 41. DESIGN REVIEW CHECKLIST

Before considering any frontend task complete, verify:

- Is the primary action clear?
- Is hierarchy obvious?
- Does this look unique to this product?
- Does Vietnamese text render correctly?
- Is spacing consistent?
- Is typography consistent?
- Is mobile experience good?
- Are loading states handled?
- Are empty states handled?
- Are errors handled?
- Are focus states visible?
- Is contrast acceptable?
- Is functionality preserved?
- Is the UI reusable?
- Is the implementation maintainable?
- Does it feel production-ready?

If not, improve it.

---

# 42. WHEN REDESIGNING A PAGE

Follow this process:

1. Inspect current page.
2. Understand its purpose.
3. Identify target users.
4. Identify primary action.
5. Identify UX problems.
6. Identify reusable components.
7. Propose visual hierarchy.
8. Implement.
9. Check responsiveness.
10. Verify functionality.
11. Polish visual details.
12. Review accessibility.
13. Review performance.

Do not immediately start coding.

---

# 43. WHEN CREATING A NEW PAGE

Before coding determine:

- page purpose
- primary user
- primary action
- content hierarchy
- required states
- mobile layout
- desktop layout
- reusable components

Then implement.

---

# 44. WHEN USER REQUEST IS VAGUE

If the user says:

"Make it better"

Do not randomly redesign.

Analyze:

- hierarchy
- spacing
- typography
- color
- consistency
- usability
- accessibility
- interaction

Then improve the weakest areas first.

---

# 45. HISTORICAL PLATFORM STANDARD

Every major screen should feel like part of a serious Vietnamese historical
knowledge platform.

The experience should combine:

Wikipedia-level usefulness
+
museum-level storytelling
+
modern educational-product usability

without directly copying any of them.

---

# 46. LONG-TERM SCALABILITY

Assume the platform may eventually include:

- thousands of historical events
- thousands of historical figures
- images
- maps
- timelines
- quizzes
- lessons
- teacher tools
- student accounts
- parent accounts
- mobile applications
- AI features
- recommendation systems
- historical knowledge graphs

Design architecture must not block future growth.

---

# 47. FINAL STANDARD

Do not ask:

"Does this look good?"

Ask:

"Would this design still feel professional if millions of users used it?"

If the answer is no,
continue improving it.

Every interface should feel intentional.

Every component should have a reason.

Every interaction should help the user.

Every design decision should support learning Vietnamese history.

Build for the long term.
